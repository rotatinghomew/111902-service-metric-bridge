# 联办指标与报送

本地合成业务资料。人名标识、去向、机构和观测均为虚构，不接入外部系统。

## 输入约定

`data/supplies.json` 以表名组织记录；`data/fields.json` 列出字段及该资料出现的值类型。

旧口径是窗口自受理到该窗口完成的工作日之差，排除窗口有效等待补件的区间；新口径是联办主体首次完整材料到最终结案间的工作日之差，只排除整件获准暂停的区间；窗口暂停事件本身不能充当全件暂停的凭据。日期区间左闭右开，同一时钟上重叠等待不重复扣除。日历默认为周一至周五，`calendar_revisions` 的适用日覆盖默认，生效时点看 `recorded`。发现完结或暂停事实不能建立时标为未能重算；资料要是只有汇总，既有旧汇总仍有效，但不能推断到单个联办件。`case_links` 里的有效责任窗口均计时，考核日期界点用 `rules`；一个居民申请归入一个 `district` 和 `service`，责任窗口可以是多个。
`recipients` 给出收件方订阅的地域和包组成；同一收件方一个上报包由一个口径截点组成。「已发送」但未收到签收和「已签收」是不同外发状态；接收回退也必须有回执。`calendar_revisions` 和 `case_links` 是业务可信来源，`signed` 代表历史签收的独立输入回执，不是现时计算的结论。

## 资料检查

在 Linux 上使用 Python 3.11 及标准库，无需安装第三方包。运行 `python3 -m unittest discover -s tests -v` 检查表字段、类型和关键关联。当前仓库只包含业务来源资料及检查，尚无分析结果或业务操作入口。
