# 联办指标与报送

本地合成业务资料。人名标识、去向、机构和观测均为虚构，不接入外部系统。

## 输入约定

`data/supplies.json` 以表名组织记录；`data/fields.json` 列出字段及该资料出现的值类型。

旧口径是窗口自受理到该窗口完成的工作日之差，排除窗口有效等待补件的区间；新口径是联办主体首次完整材料到最终结案间的工作日之差，只排除整件获准暂停的区间；窗口暂停事件本身不能充当全件暂停的凭据。日期区间左闭右开，同一时钟上重叠等待不重复扣除。日历默认为周一至周五，`calendar_revisions` 的适用日覆盖默认，生效时点看 `recorded`。发现完结或暂停事实不能建立时标为未能重算；资料要是只有汇总，既有旧汇总仍有效，但不能推断到单个联办件。`case_links` 里的有效责任窗口均计时，考核日期界点用 `rules`；一个居民申请归入一个 `district` 和 `service`，责任窗口可以是多个。
`recipients` 给出收件方订阅的地域和包组成；同一收件方一个上报包由一个口径截点组成。「已发送」但未收到签收和「已签收」是不同外发状态；接收回退也必须有回执。`calendar_revisions` 和 `case_links` 是业务可信来源，`signed` 代表历史签收的独立输入回执，不是现时计算的结论。

## 资料检查

在 Linux 上使用 Python 3.11 及标准库，无需安装第三方包。运行 `python3 -m unittest discover -s tests -v` 检查表字段、类型和关键关联，并回归重算、汇总、组包、回执与更正的逻辑。

## 操作入口

业务代码在 `timeliness/`，结果与本地回执写在 `results/`（不入库）。常用顺序：

```bash
# 1) 按口径截点重算：旧约定与新版同时给出，未能重算的列出缺口
python3 -m timeliness.cli compute --cutoff 2026-11-04T18:00
# 2) 已签收包受事实更正影响的，生成更正说明（本期更正 + 不再成立的对比区间）
python3 -m timeliness.cli correct --now 2026-11-04T18:00
# 3) 未送出的包按同一套有效事实重核重出；已签收的收件方不重复收包
python3 -m timeliness.cli bundle --all --period 2026-10 --cutoff 2026-11-04T18:00
# 4) 送出前整包重核，任一组成口径不一致则整包拦截
python3 -m timeliness.cli send --bundle R02 --at 2026-11-05T08:00
# 5) 经办人追溯退回的比较项：哪段历史材料或哪种适用口径不支持它
python3 -m timeliness.cli trace --item new:K2
python3 -m timeliness.cli compare --a legacy:2026-09/北城/居住联办/W3 --b new:K1
python3 -m timeliness.cli status
```

约定要点：

- 一个上报包 = 一个收件方 + 一个期间 + 一个口径截点；组成按 `recipients` 订阅，旧考核、新考核、覆盖说明不互作替代。
- 本地回执（`results/outbox.json`）区分生成、送出、签收、退回、作废、受阻；`signed` 表只作历史播种。已签收的包不能追改，只能出更正说明；未送出的包在事实变化后必须整包重出，不允许只更新能算的一张就发送整包。
- 旧口径分母按组件计（每个责任窗口各计一件）；新口径分母按联办件计（只算一次）。涉及窗口切片仅供拆开查看，合计按联办件去重，不可按行相加。
- 比较只标注差异来源（事项组合、适用日期、口径、事实版本），跨口径或跨粒度判定为不可直接比较，不得把变动归结为办得更快了。
- `首次完整材料` 取各有效组件最早的`材料齐备`；`最终结案`取最早的`联合结案`；窗口暂停/恢复不充当全件暂停凭据，新口径只认`全件暂停/全件恢复`。
